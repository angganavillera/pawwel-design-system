Overview

Design Guidelines

This guide documents the PAWWEL design system in a cleaner, scrollable format for design handoff, collaboration, and implementation reference. It provides direct access to components, tokens, spacing, motion, and interaction rules without requiring deep inspection of Figma source files.

✨
Standards of Behavior
System consistency is maintained through a token-driven ecosystem. Semantic tokens define behavioral intent, while primitive values may still be used for foundational mapping when needed. The primary rule is to avoid hardcoded values to preserve flexibility, scalability, and accessibility across the experience.
Core Principle

Design Philosophy

PAWWEL is a companion app, not a pet tracker. Every design decision must reinforce the emotional connection between the user and their pet — mediated through the PAWWEL robot.

🧡
Emotional over Data
Show "Apple seems calm today" not "Anxiety score: 2.3". Interpret, don't report.
🍎
Apple-Level Polish
Use native iOS materials, physics-based animations, and system haptics. Never fight the platform.
🌿
Breathable Layout
Generous whitespace. Hierarchy through scale and weight, not borders and boxes.
😊
Robot as Character
PAWWEL is a companion, not a device. States, expressions, and animations must reflect personality.

Anti-patterns to avoid

✓ Do
  • Use named emotional states ("Calm & Happy", "Playful", "Needs Attention")
  • Prioritize narrative cards over data tables
  • Warm, organic color palette (brown/orange foundation)
  • Spring-based animations for natural feel
  • Sora for all primary interface typography
✗ Don't
  • Show raw sensor data or decimal scores
  • Use cold blues, purples, or enterprise palettes
  • Heavy borders everywhere (dashboard aesthetic)
  • Linear easing for UI transitions
  • Mixing other body fonts with Sora
Foundation

Token Architecture

The PAWWEL system uses a 3-tier hierarchy to move from raw visual materials to specific functional behaviors.

1
Foundational Values
The raw palette and spacing scales that define the system's emotional range. These serve as the base for all higher-level decisions.
2
Functional Intent
Behavior-named aliases that define how elements relate to the user, such as active states, surface depth, or text hierarchy.
3
Contextual Application
The final application layer where intent maps to specific components, ensuring they respond predictably to various emotional and system states.
Rely on Intent
  • Define hierarchy through behavioral tokens like fg.primary and bg.secondary to ensure consistency.
  • Using tokens allows the interface to remain dynamic across environmental shifts and accessibility modes.
  • Every interaction should map to an existing behavioral intent to maintain system coherence.
Avoid Fixed Values
  • Hardcoded color or spacing values break the system's ability to scale and adapt.
  • Bypassing the token library creates visual debt and inconsistent user experiences.
  • Static markers limit the product's ability to respond to emotional state changes or user preferences.

Design Rules

Do
  • Resolve every visual decision from type, size, isIcon, and isDisabled.
  • Use semantic tokens for surface, foreground, border, radius, spacing, and motion.
  • Scale icon-only dimensions and icon-label gap with the selected size.
  • Disabled removes interaction, not only visual prominence.
Do Not
  • Reach for hex values, ad-hoc padding, or local corner radius.
  • Invent button variants that don't exist in Figma.
  • Treat disabled as a type — it is a state that applies to every type and size.
  • Let icon-only buttons shrink below the platform touch target.

Interaction Behavior

State Visual response Motion
Rest Default tokens for the chosen type. None.
Pressed Subtle inward compression — feels physical, never theatrical. spring.snappy · ~3% scale reduction.
Focused 2pt outer ring in color.border.active, offset 2pt from the button edge. Fade in duration.fast.
Loading Label is replaced with an inline spinner; size and width are preserved. Cross-fade duration.fast.
Disabled Disabled tokens, ~72% opacity, no hit-testing. Instant.

Content Guidelines

  • Lead with a verb. Labels describe an action, not a destination — Give Treat, not Treat Page.
  • Keep labels to 1–3 words. Sentence case. No trailing punctuation.
  • One Primary per view. Multiple Primaries flatten hierarchy.
  • Destructive labels name the consequence — Delete Moment, never Confirm.
  • Icon-only buttons require a VoiceOver label that reads as a verb.
📐
Minimum touch target: 44pt
All interactive elements must meet iOS HIG 44×44pt minimum. Use .frame(minHeight: 44) even on small-looking elements. Do not rely on visual padding alone.

Interaction Behavior

Rule Behavior
Trigger Tap on the anchor element. No hover, no long-press required.
Single instance Only one tooltip visible globally. Opening a new tooltip dismisses the active one.
Tap outside Tap on any region outside the tooltip and its anchor dismisses it immediately.
Escape key Where a hardware keyboard is present (iPad, Mac Catalyst), Esc dismisses.
Persistence Tooltip stays visible until explicitly dismissed. No auto-timeout — content is read at the user's pace.
Scroll Tooltip dismisses on scroll of the underlying view to avoid stale positioning.

Placement Rules

Placement is requested via the arrow property but resolved dynamically. The runtime auto-repositions to the nearest valid edge if the requested placement would clip the viewport or cross a safe-area inset.

Priority Rule
1 Honor the requested arrow position when content fits within viewport + safe areas.
2 Flip to the opposite edge if the primary placement clips (e.g. top → bottom).
3 Shift along the cross-axis to keep the tooltip on screen; arrow offset moves with the shift.
4 If neither edge fits, fall back to arrow-none centered overlay.
5 Maintain a minimum 12pt gap from the screen edge and respect safeAreaInsets on every side.
6 Width adapts to content between 120pt and 280pt; wraps to multiline beyond.

Motion Specs

Phase Properties Duration Easing
Enter opacity 0 → 1, translateY +6pt → 0 200ms ease-out / spring (response 0.32, damping 0.86)
Exit opacity 1 → 0, translateY 0 → +4pt 150ms ease-in
🪶
Keep motion breathable
No bounce, no scale-up, no rotation. The tooltip should feel like it's fading into place — never announcing itself. If a user notices the animation, it is too loud.

Accessibility

Required
  • Anchor element must expose a 44×44pt minimum touch target, even when the visual is smaller.
  • Provide a VoiceOver label on the anchor describing the tooltip purpose (e.g. "Help: Robot status").
  • Tooltip body uses Dynamic Type — must remain readable at .accessibility3 and above without truncation.
  • Pair every color cue with a text or icon cue; never rely on color alone.
  • On open, move VoiceOver focus to the tooltip and announce its content.
Avoid
  • Auto-dismissing on a timer — users with cognitive or motor differences need to read at their pace.
  • Embedding interactive controls inside the tooltip (links, buttons). Keep it informational.
  • Overflowing the screen horizontally; let the tooltip wrap rather than truncate.
  • Hiding critical information behind a tooltip — it must be supplementary, never required.

Content Guidelines

  • Titles are short and noun-forward — Robot Status, not What is Robot Status?.
  • Descriptions explain in one sentence. If two sentences are needed, the surface is wrong; use a sheet instead.
  • Tooltips are supplementary. Critical information lives in the main UI — never behind a tap.
  • Avoid links, buttons, or any action inside a tooltip. It is read, not used.

Design Rules

Do
  • Use semantic tokens for surface, foreground, border, radius, and shadow.
  • Anchor placement to the trigger; let the runtime resolve the safe position.
  • Let width adapt to content within the 120–280pt range.
  • Dismiss on tap outside, on scroll, or when another tooltip opens.
  • Mirror the Figma variant set 1:1 — no extra states.
Do Not
  • Hardcode hex, fixed widths, or absolute screen positions.
  • Show more than one tooltip on screen at once.
  • Add hover-based triggers, scaling, or bouncing entrance animations.
  • Auto-dismiss on a timer or block underlying content with an opaque scrim.
  • Place required actions or critical information inside a tooltip.
📐
Anchor must meet 44pt minimum
The tooltip itself is non-interactive, but its anchor must satisfy iOS HIG 44×44pt. The trigger must remain comfortably tappable even when the icon is visually smaller.

Pills & Status Chips

Pills carry emotional state. They are never decorative. Every pill pairs a colored dot with a text label — color is reinforcement, never the carrier of meaning.

Calm & Happy Playful Slightly Uneasy Needs Attention Overstimulated Resting

Emotional Intent

State Surface Dot What it tells the owner Robot expression
Calm & Happy state.success.primary green.60 Pet is emotionally safe and connected. Slow breathing, soft attention.
Playful yellow.10 yellow.60 Energetic, curious, cheerful — never urgent. Bouncy movement, bright response.
Slightly Uneasy color.base.brown.30 brown.70 Subtle discomfort. Owner can check in, but no alarm. Gentler idle, slower gaze shifts.

Behavior

Rule Expectation
Pairing Dot + label always travel together. A pill without a label is not a valid component.
Transitions State changes cross-fade with spring.default. Never snap.
Multiplicity One pill per surface. Stacked pills compete for attention and dilute meaning.
Truncation Labels never truncate. If text wraps, the surface grows — pills are content-shaped.
Tone Wording is descriptive and supportive (Slightly Uneasy, not Anxious). Pills do not diagnose.

Content Guidelines

  • Headlines read like a moment, not a metric. Apple had a zoomies moment, not Activity spike detected.
  • Narrative copy stays under two lines. Beyond that, the card opens to a full view — the card is a hook, not the story.
  • Timestamps are relative when recent (Today · 3:42 PM) and shift to dates after 24 hours.
  • Every card carries one emotional state pill, anchored to the moment — not the current pet state.
  • If imagery is missing, fall back to a tinted surface in the moment's emotional accent color, not a generic placeholder.

Behavior

Rule Expectation
Tap Opens the full Moment view. Press uses spring.snappy with a ~2% scale dip — never a flash.
Long-press Reveals contextual actions (Save, Share, Delete) via a native quick-action menu.
Loading Skeleton matches the card's shape and image area. Shimmer is calm — see Loading States.
Image failure Replace with the emotion-tinted surface; the narrative remains readable on its own.
Hierarchy Image first, then headline, then narrative, then timestamp meta. The eye should travel in that order without effort.
📖
A moment is a story, not a data point
If a card could be replaced by a row in a table without losing meaning, it isn't doing its job. Every card should leave the owner with a small feeling — recognition, warmth, mild concern — not just information.

Behavior

Rule Expectation
Presentation Sheet rises from the bottom edge with native iOS physics. Never a fade or slide-from-side.
Detents Default to a medium detent. Promote to large only when the content genuinely needs the height.
Drag handle Always visible. The handle communicates that the sheet can be dismissed by gesture, not just by tapping outside.
Scrim Dimmed underlay using color.bg.overlay. Tapping the scrim dismisses the sheet.
Dismissal Drag-down, tap scrim, or system back gesture all dismiss. There is always a way out without using a button.
Stacking Only one sheet at a time. A new sheet replaces, never stacks.
Component

Loading & Skeleton States

Loading states should feel calm and match the emotional tone of PAWWEL — not jarring spinners. Use content-shaped skeletons.

Behavior

Rule Expectation
Shape Skeletons mirror the final layout — image area, headline line, two body lines, meta. Never a generic block.
Color Surface drifts gently from brown.10 through brown.20 and back. No high-contrast shimmer.
Cadence Loop is slow — roughly 1.4s per pass. The eye should read patience, not progress.
Radius Always match the parent component's radius. A skeleton inside a 24pt card never has its own corner language.
Reduce Motion When Reduce Motion is on, the shimmer holds at its mid-tone instead of looping.

Motion Principles

  • Motion has weight. The robot breathes, the cards settle, the sheets fall into place. Nothing snaps into existence.
  • Motion reinforces, never announces. If the user notices the animation more than the change, the motion is too loud.
  • Looped motion stays calm. Idle and breathing loops use long springs so the eye reads life, not activity.
  • One-shot motion has personality. Treat dispense, outfit changes, and celebrations are allowed to be playful — but always brief.
  • Reduce Motion is honored everywhere. All idle loops, transitions, and decorative motion collapse to an instant change when the system requests it.

Principle: Name the feeling, don't measure it
Always display the emotional interpretation ("Apple needs attention right now") rather than the raw score. Users are pet parents, not data scientists. The number lives in the system — only the story reaches the screen.
